# 画面ラフ（任意）

Phase 4 で、依頼者が「画面で見せたい」「絵にしてほしい」と言ったときだけ使う。こちらから毎回すすめない。

目的は **依頼者の案を伝えること**。見た目を完成させることではない。細部（余白・文言・色）を詰め始めたら、「細かいところはエンジニア・デザイナーと決めるので、ここでは方向性が伝われば十分です」と戻す。

## 作り方

Claude の「Design」アーティファクト（キャンバスに画面を並べて見られる形式）で作る。Artifact ツールの quickstart（intent: design）から始め、返ってきた手順に従う。

1. **既存の画面を再現する**（既存の画面に手を加える案のとき）
   - リポジトリあり：対象画面のコードを読み、画面の構成（ヘッダー・検索欄・表など）、配色やフォント、余白、ボタンの形を写す。配色などは、デザインの値をまとめたファイル（色・余白・角丸の定義）があればそこから取る
   - リポジトリなし：依頼者のスクリーンショットから近い画面を作る。再現の精度は落ちることを伝える
   - ロゴなどの画像がリポジトリにあれば、アップロードして使う
   - Design System（会社のデザインの部品集）が登録されていれば、それを使う
2. **依頼者の案を足す**：再現した画面をもう1枚複製し、案を反映した画面を横に並べる。「今」と「案」を見比べられるようにする
3. 状態の違い（0件のとき・読み込み中など）が話に関係するなら、切り替えて見られるようにしておく

## 注意すること

- 表に入れるデータは **ダミー** にする。実在のお客様や企業の名前・個人情報を入れない
- ログイン後の画面や実データで変わる部分は、コードから想定して描く。想定で描いた部分があることを依頼者に伝える
- 作った画面は依頼者本人しか開けない。エンジニアやチームに見せるには、依頼者が画面の共有メニューから共有する必要があることを伝える
- 要求ドキュメントの「6. 依頼者のアイデア」の「画面ラフ」にリンクを書き、「依頼者の案（変更可）」であることを添える
