# 要求ドキュメントの出力（Phase 7）

要求ドキュメントは、基本は Claude の Artifact の **Document（Claude Docs）** に書く。1つの依頼を、Document の tabs（Document の中のタブの一覧）の1タブにする。Document はキャンバスではないので、ページではなくタブで分ける。依頼者が選んだときは md ファイルに出力する。

## 0. 出力の形を選んでもらう

出力する前に、AskUserQuestion で依頼者に選んでもらう。

> 要求ドキュメントをどの形で出力しますか？

- 「Claude の Document に書く（推奨）」：説明は「チームで共有・コメント・直接編集ができます」
- 「md ファイルに出力する」：説明は使っている環境に合わせて、次のどちらかにする。保存先のパスなど、依頼者に関係のない言葉は書かない
  - Claude Code でリポジトリを開いているとき：「ファイルとして共有できて便利です（リポジトリの中に保存します）」
  - Claude のアプリのチャット（Claude Desktop・claude.ai）から使っているとき：「ファイルとして共有できて便利です（ダウンロードできます）」

Document を選んだら 1〜5 の手順で進める。md を選んだら「md ファイルに出力するとき」の手順で進める。Claude Docs のツールがない環境では聞かずに md にし、「この環境では Document を作れないため、md ファイルで出力します」と伝える。

## Document に書くとき

Document の操作（作成・タブの追加・書き込み・読み返し）は、Claude Docs のツールで行う。最初の操作の前に Claude Docs の guide（`topic.index`。既存の Document にタブを足すときは `topic.tabs` も）を読み、その書き方に従う。

### 1. 書く場所を決める

ユーザーには聞かず、Claude が判定する。

| 状況 | 書く場所 |
|---|---|
| リポジトリなし（何らかのリポジトリに対する要求ではない） | 新しい Document を作る |
| リポジトリあり・要求用の Document の URL が記録されている | **その Document の tabs に新しいタブを足す** |
| リポジトリあり・要求用の Document の URL が記録されていない | 新しい Document を作る |

**要求用の Document の URL の探し方**（リポジトリありのとき）

開発ルールをまとめた資料等に、要求ドキュメントの置き場所として記録されていないかを確かめる。記録の場所はリポジトリによって違うため、特定のファイルに決め打ちしない。

- 開発ルールをまとめた資料（例：`CLAUDE.md`、`README.md`、`CONTRIBUTING.md`、`docs/` 配下の開発ルール・要求の資料）
- 上で見つからなければ、リポジトリ内を `claude.ai/artifact/`・`claude.ai/code/artifact/` で検索し、要求用・依頼用と書かれているもの
- 見つかった URL は Claude Docs のツールで読み、Document であること（タブの一覧が返ること）を確かめる。Document でない・読めないときは、記録されていないものとして扱う
- 要求用らしい Document が複数あって決められないときは、依頼者に「どちらに追加しますか？」と選んでもらう
- 仕様書用の Document（spec-interview の記録先）には書かない。要求ドキュメントと仕様書は別々の Document にする

### 2. Document を作る・タブを足す

**新しい Document を作るとき**

- リポジトリなし：Document の名前は `要求：<短い名前>`。タブは1つ
- リポジトリあり：次回以降も使い回せるよう、Document の名前は `<リポジトリ名・プロダクト名> 要求ドキュメント` にし、今回の依頼はタブ `YYYY-MM-DD <短い名前>` として書く

**既存の要求用 Document にタブを足すとき**

- タブ `YYYY-MM-DD <短い名前>` を新しく足す。**既存のタブは書き換えない**
- タブの並びは既存の並び方（日付順など）に合わせる
- タブを足せなかった（編集できない・拒否された）ときは、新しい Document を作り、「既存の要求ドキュメントは編集できなかったため、別に作りました」と依頼者に伝える

### 3. 中身の書き方

- `assets/request-template.md` の構成で書く。冒頭の「概要」の表の行の名前は変えない（spec-interview が要求ドキュメントを見分けるのに使う）
- 「状態」はプルダウンにし、最初は「ヒアリング中」にする。9. 事前確認の「状態」の列もプルダウン（確認済み / 要確認 / 該当なし）にして良い
- `<短い名前>` は依頼内容を表す日本語か英語の短い言葉（例：`請求書の再発行`）
- 書き始めたら Document を開いて依頼者に見せ、セクションを1つずつ埋めていく（依頼者が埋まっていく様子を見られるようにするため）
- ローカル PC の絶対パス（`/Users/...`）は書かない。リポジトリ内のパスは書いて良い
- Phase 6 で画面デザインを作ったときは、その URL を「概要」の表の「画面デザイン」と「6. 依頼者のアイデア」の両方に書く

### 4. 読み返し

- 依頼者に Document を読んでもらう。直したいところは、チャットで伝えてもらうか、Document に直接書き込む・コメントを付けてもらう
- 依頼者が Document を直接直したときは、その直しを優先し、Claude が上書きしない
- 合意が取れたら、「状態」を「合意済み」にする

### 5. 共有と、次回以降の使い回し

Document と Design は、作った直後は依頼者本人しか開けない。Claude からは共有できないので、依頼者に操作を案内する。

- **共有**：Document（と画面デザイン）の画面上部の **Share** から、エンジニアやチームの人を追加してもらう。既存の要求用 Document にタブを足したときは、そこに入っている人はもう見られるが、今回渡すエンジニアが入っているかを確認してもらう
- **次回以降の使い回し**（リポジトリありで、Document を新しく作ったとき）：リポジトリには Claude から書き込まない。代わりに、Document の URL を添えて次のように伝える

  > 今後も要求定義の結果をこの Document に追記していく場合は、本リポジトリに記録先として記載してください（担当者がいるのであれば、その方に依頼してください）。

  画面デザイン（Design）を新しく作ったときも、同じ文面で「Document」を「Design」に読み替えて伝える

- **Notion に残したいとき**：Document の名前をクリック → **Export** → Notion で、開いているタブを Notion にコピーできることを案内する（`config.md` に Notion の記録先があれば、その名前も添える）

## md ファイルに出力するとき

- 置き場所は、使っている環境で変える。ファイル名はどちらも `YYYY-MM-DD-<短い名前>.md`

  | 環境 | 置き場所 |
  |---|---|
  | Claude Code でリポジトリを開いている | `docs/requests/YYYY-MM-DD-<短い名前>.md`（`docs/requests/` がなければ作る） |
  | Claude Code で、リポジトリではないフォルダを開いている | カレントディレクトリ（依頼者が場所を指定したらそこ） |
  | Claude のアプリのチャット（Claude Desktop・claude.ai） | リポジトリやフォルダには置かず、**チャットからそのままダウンロードできるファイル** として渡す。ファイルを作って渡す機能（ファイルの出力・共有）があればそれを使う。ない環境では、md の中身を1つのコードブロックにまとめて表示し、コピーして `.md` で保存してもらう |

- Claude のアプリのチャットで、読み返しで直しが入ったときは、直した版のファイルを作り直して渡し直す（古いファイルを使わないよう、「こちらが最新です」と添える）
- 中身は `assets/request-template.md` の構成にする。「概要」の表はそのまま md の冒頭に置き、「状態」は「ヒアリング中」「合意済み」の文字で書く（spec-interview は md の要求ドキュメントも受け取れる）
- 読み返しは Document のときと同じ。直しは Claude が md に反映し、合意が取れたら「状態」を「合意済み」にする
- 最後に、ファイルの場所（チャットの場合は、ダウンロードの仕方）と、ファイルを添付して共有できることを伝える。リポジトリに置いたときは、コミットして共有できることも伝える。Notion に残したいときは、ファイルの中身を Notion に貼り付ければ良い
- 画面デザインを新しく作ったときの「次回以降の使い回し」の伝え方は、Document のときと同じ（「Document」を「Design」に読み替える）
