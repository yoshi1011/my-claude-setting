# Obsidian でのユーザープロフィール管理

ユーザーの好みや過去の仕様設計の記録を Obsidian の Vault に保存し、次回以降の仕様設計で活用する。

## 場所

Vault のパスは、このスキルフォルダ内の `config.md` の「仕様設計ナレッジの保存先」から取得する。この Vault は仕様設計の情報を蓄積するための専用の場所であり、仕様設計以外の作業では読み書きしない。

`config.md` がない、またはパスが未記入の場合はユーザーに聞き、`config.md` への記入を提案する。

Vault 内の構成：

```
{Vault}/
└── Claude/
    ├── spec-profile.md          … ユーザープロフィール（1ファイル）
    └── specs/
        └── {プロジェクト名}.md   … プロジェクトごとの仕様設計の記録
```

フォルダやファイルがなければ作成する。

## 読み込み（Phase 0）

1. `{Vault}/Claude/spec-profile.md` を読む
2. 今回の依頼と近い過去プロジェクトが「過去のプロジェクト」にあれば、そのノートも読む
3. 読み取った好みを、以降のフェーズで使うデフォルト案として手元にまとめる

確度が「低」の項目はデフォルト案にせず、参考程度に留める。

## 書き込み（Phase 8）

ユーザーの同意を得てから書き込む。追記・変更する内容を次のように一覧で見せる。

> 今回の仕様設計から、プロフィールに以下を反映しようと思います。
> - 追加：技術スタック「データ保存は最初はブラウザ内保存で始める」（確度：低）
> - 更新：デザインの好み「シンプル寄り」を確度：中 → 高に
> - 追加：よく対象外にする項目「PERF（個人ツールの場合）」（確度：低）
> この内容で書き込んで良いですか？

### 記録のルール

- 1回のプロジェクトだけで分かったことは「確度：低」とする。複数のプロジェクトで同じ判断があれば「中」「高」へ上げる
- 過去の記録と異なる判断をした場合は、上書きせず「例外」として両方残し、どういう条件で変わったかを書く（例：「普段はシンプル寄りだが、店舗サイトでは写真を大きく使う」）
- 根拠として、どのプロジェクトで分かったかを `[[リンク]]` で残す
- 一般論や推測は書かない。ユーザーが実際に選んだこと・言ったことだけを書く

## spec-profile.md のテンプレート

```markdown
---
tags: [claude, spec-profile]
updated: YYYY-MM-DD
---

# 仕様設計プロフィール

## 技術スタックの好み
- Next.js + Tailwind CSS（確度：高）根拠：[[作業ログ管理ツール]]、[[ポートフォリオサイト]]

## デザインの好み
- シンプル寄り、余白多め（確度：中）根拠：[[ポートフォリオサイト]]
  - 例外：店舗サイトでは写真を大きく使う [[〇〇カフェ]]

## よく対象外にする項目
- PERF：個人ツールでは重視しない（確度：低）根拠：[[作業ログ管理ツール]]

## 判断の傾向
- 入力の手間を減らすことを最優先する（確度：中）

## ヒアリングの好み
- 選択肢形式で聞かれる方が答えやすい（確度：高）
- 一度に聞かれるのは2問程度まで（確度：中）

## 過去のプロジェクト
- [[作業ログ管理ツール]] 2026-10
- [[ポートフォリオサイト]] 2026-08
```

## プロジェクトノート（specs/{プロジェクト名}.md）のテンプレート

仕様書の全文は各リポジトリの `docs/spec.md` にあるため、ここには振り返りに役立つ要点だけを残す。

```markdown
---
tags: [claude, spec]
date: YYYY-MM-DD
repo: {リポジトリのパス}
type: {完全新規 / 追加実装}
---

# {プロジェクト名}

## ゴール
（Phase 1 のゴールを一文で）

## 主な決定事項
（重要な判断とその理由を数行で）

## 対象外にしたもの
（項目と理由）

## 次に活かせること
（ヒアリングで時間がかかった点、後から追加になった点など）

関連：[[spec-profile]]
```
